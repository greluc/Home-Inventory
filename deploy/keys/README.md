# `deploy/keys/` — public keys, and only public keys

This directory holds **public** halves of signing keys. Nothing here is secret,
nothing here is generated by `setup.sh`, and nothing here is ever a private key.

| File | What it is | Who made it |
|---|---|---|
| `home-inv-plugins.pub.pem` | The key this project signs its own plugin manifests with (`REQ-PLG-004`, [ADR-0085](../../docs/adr/0085-a-manifest-signature-is-checked-offline-and-an-image-is-not.md)) | the maintainer, once |

`setup.sh` seeds every `cosign-plugin-*` secret from the file `services.yaml`
names in that secret's `seedFrom:`. A third party's plugin names no file this
repository holds, so its secret is written empty and the operator puts that
publisher's key there — which is the same act as supplying any other value that
belongs to somebody else's system.

## A private key is never in this repository, and never in a runner

CI runs `python tools/manifest_signatures.py --check`, which needs the public
half and nothing more. Signing is a **person's command** with a key that person
holds:

```bash
python tools/manifest_signatures.py --sign --key path/to/cosign.key
```

The reason is the rule this repository already applies to every other
credential: anything that enters a worktree, a CI log or a container volume must
be assumed leaked. A long-lived signing key in a build is the one secret whose
leak cannot be repaired by rotating it quietly — every signature it ever made
becomes worthless, and every deployment that trusted it has to be told.

## Creating the key, once

```bash
cosign generate-key-pair
```

`cosign.pub` is the public half and belongs here as
`home-inv-plugins.pub.pem`; `cosign.key` is the private half and belongs
nowhere near this directory. `openssl` produces an interchangeable pair, because
signing a blob with a key is SHA-256 followed by ECDSA in both:

```bash
openssl ecparam -name prime256v1 -genkey -noout -out cosign.key
openssl ec -in cosign.key -pubout -out deploy/keys/home-inv-plugins.pub.pem
```

## Until the manifests are signed

`home-inv-plugins.pub.pem` is **not here yet**, and neither are the
`plugins/*/manifest.yaml.sig` files. Every first-party plugin therefore verifies
as *unsigned*, which is an honest state and a visible one: the core registers it
`DISABLED` with a reason naming `HOMEINV_PLUGINS_ALLOW_UNSIGNED`, rather than
pretending a check happened.

Running the two commands above and committing what they produce is the whole of
what turns that into a verified signature — no code changes, no configuration.
