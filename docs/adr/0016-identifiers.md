# ADR-0016 — UUIDv7 internally, a separate public short code

**Status:** Accepted · **Date:** 2026-09-11

## Context

Every item is to be identified by a UUID; physical items additionally by a
printed code. The question is whether those can be the same thing.

## Decision, part 1: UUIDv7 as the primary key

| Option | Assessment |
|---|---|
| `bigserial` | Not generatable offline by the client; reveals the size of the inventory; reconciliation across several devices impossible |
| UUIDv4 | Generatable offline, but randomly distributed → B-tree indexes fragment, insert performance and cache hit rate suffer noticeably |
| **UUIDv7** | Time-ordered (as index-friendly as a sequence), generatable offline, globally unique; built into PostgreSQL 18 as `uuidv7()` |

**UUIDv7**, generated by the client (the prerequisite for offline creation) or by
the server.

## Decision, part 2: the public code is not the UUID

What gets printed is a separate **short code**: 8 payload characters plus a check
character from the **Crockford Base32** alphabet, cryptographically random,
globally unique, linked to an entity through a `CodeBinding` table.

| Reason | Explanation |
|---|---|
| **Print size** | 36 characters yield a QR code of version 3–4; 9 characters fit into version 1–2 and stay sharply readable on 25 × 10 mm |
| **Readability** | A label must still be useful when the scan fails. You can type `7Q2-M4X-9KD`; you cannot type a UUID |
| **Decoupling** | A label can be reassigned; the code hangs on a binding, not on the identity. The binding history remains |
| **Information leakage** | UUIDv7 contains a timestamp. On a label that any visitor can scan, that is needlessly given away |

The alphabet omits `I`, `L`, `O` and `U`: no confusing `0`/`O` or `1`/`I`, and no
accidental profanity.

## Consequences

- `UNIQUE(code)` is **global**, not per tenant — otherwise a scan could not be
  resolved unambiguously. The code reveals nothing about the tenant.
- 40 bits of randomness give about 1.1 · 10¹² possibilities; enumeration is
  hopeless with rate limiting. On a collision a new code is drawn.
- **Pre-issuing**: codes can be generated and printed before the item exists. The
  fastest capture path there is.
- The QR code contains a URL (`/c/<code>`) so that any camera app works, plus the
  UUID in the **fragment** (`#i=<uuid>`) for offline resolution. The fragment
  never reaches the server.
- **The base URL is deployment configuration** (`HOMEINV_PUBLIC_BASE_URL`), not
  hard-coded. It is nevertheless printed onto every label and is thus the only
  configuration value that writes itself into the physical world. The safeguards
  — confirmation before the first print, a startup warning with the number of
  affected labels, a banner during operation, `HOMEINV_LEGACY_BASE_URLS` for old
  hostnames and a documented migration path — are in
  [10 §10.2.1](../architecture/10-identification-and-labels.md).
- Foreign codes (ISBN, EAN) are bound **in addition** as an `ExternalCode`, not
  instead of our own code.
